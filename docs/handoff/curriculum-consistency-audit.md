## Part 1 — Cross-chapter facts

- ml-systems.gpu/01-why-accelerators-are-fast.md:210 — The A100 row paired 2 TB/s with both 40 and 80 GB → distinguish the 40 GB bandwidth from the 80 GB SXM example and name the roofline SKUs (`ml-systems.gpu/02-arithmetic-intensity.md:30` uses the 2 TB/s case, `ml-systems.inference-optimization/01-the-inference-bottleneck.md:61–65` couples it with 80 GB, and the [NVIDIA A100 datasheet](https://www.nvidia.com/content/dam/en-zz/Solutions/Data-Center/a100/pdf/nvidia-a100-datasheet-us-nvidia-1758950-r4-web.pdf) gives 1,555 and 2,039 GB/s for the two SXM cards).
- ml-systems.inference-optimization/01-the-inference-bottleneck.md:136,197 — Two fixed ranges were applied to GQA and MQA → KV size follows the number of KV heads, which also changes KV read traffic (`ml-systems.inference-optimization/02-memory-and-attention.md:198–204` contrasts eight heads with one at 32 query heads, and `llm.architecture/01-the-transformer-block.md:157–166` gives the general head counts).
- ml-systems.vector-search/02-operating-retrieval.md:222 — Recall@k was a yes/no question about one document → use the fraction of relevant documents in the top k (`ml-foundations.evaluation/01-model-evaluation.md:137` defines the denominator as all relevant items).
- ml-systems.evaluation-infra/03-evaluating-generative-systems.md:110 — Recall@k used a single answer-bearing document as its general definition → use the fraction of answer-bearing documents, with yes/no as the one-document special case (`ml-foundations.evaluation/01-model-evaluation.md:137`).
- ml-systems.cost/01-where-the-money-goes.md:214 — API crossover compared dollars per million tokens with self-hosted dollars per token → scale the self-hosted cost to a million tokens (`ml-systems.cost/01-where-the-money-goes.md:303–311` gives a same-unit worked comparison, and `ml-systems.serving/03-scaling-and-operations.md:196–197` uses the same denominator conversion for cost per 1,000 predictions).
